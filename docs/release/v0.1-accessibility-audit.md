# Stow v0.1 Accessibility and Presentation Audit

- Date: 2026-08-09
- Scope: newest available iPhone simulator and current macOS host (ADR 0004)
- Result: Pass in the owner-approved automated scope

## iPhone

`StowUITests` runs XCTest accessibility audits for the standard interface and dark mode with Reduce Motion enabled. A separate accessibility-XXXL test verifies that the primary empty-state action remains reachable by scrolling. The audit drove fixes for hit target size, text clipping, Dynamic Type layout, and empty-state contrast.

## macOS

`StowMacUITests` queries all management destinations and the bottom quick panel through the accessibility hierarchy. The panel exposes its window, Clipboard/Inbox/Pinned modes, content-native cards, search field, removable filter tokens, no-results state, edit/preview popovers, Quick Add controls, and an always-visible `Close Quick Panel` control with stable labels and identifiers. `Clear Search` and `Close Quick Panel` have distinct names, locations, and keyboard behavior. The toolbar states whether Return uses Direct Paste or Copy only and reports paused monitoring without relying on color alone.

Automated coverage includes the registered global shortcut from TextEdit without changing the frontmost app, explicit/shortcut/outside close routes, layered More/Escape behavior, focus handoff, clean and dirty cancellation, discard confirmation, failed-save draft preservation, stale search fallback, fullwidth query input, destination handoff, successful drag completion, keyboard copy/edit/Space-preview actions, normal and compact layouts, a 480 pt narrow layout, dark appearance, Reduce Motion, and Increase Contrast. Selection uses a thick accent outline in addition to color. Confirmation receives focus before destructive draft discard, while `Keep Editing` returns to the editor. Global shortcut registration and direct-paste Accessibility state have visible, non-sensitive status and fallback guidance in Settings. The bounded visual capture set in `docs/release/v0.1-quick-panel-visual-review.md` passes inspection for overflow, truncation ambiguity, contrast-state semantics, and distinct Close/Clear placement.

The owner-approved release scope does not use VoiceOver and is limited to the current single-display Mac. Named-control, status, focus, confirmation, keyboard-exit, and originating-app restoration assertions provide the macOS accessibility evidence; no multi-display check is required for v0.1.

## Privacy and sensitive previews

All root content is marked privacy-sensitive. When the iOS scene is inactive, Stow overlays saved content with an opaque material and a generic “Stow is private” message. Stow does not schedule notifications containing saved content.

## Localization readiness

All user-facing static SwiftUI literals use localized string-key initializers. `xcodebuild -exportLocalizations -exportLanguage en` successfully produced an English localization catalog. Dynamic item titles, content, filenames, dates, and source-app names intentionally remain user/system data rather than localization keys.
