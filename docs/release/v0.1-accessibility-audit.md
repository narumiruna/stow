# Stow v0.1 Accessibility and Presentation Audit

- Date: 2026-08-09
- Scope: newest available iPhone simulator and current macOS host (ADR 0004)
- Result: Pass in the owner-approved automated scope

## iPhone

`StowUITests` runs XCTest accessibility audits for the standard interface and dark mode with Reduce Motion enabled. A separate accessibility-XXXL test verifies that the primary empty-state action remains reachable by scrolling. The audit drove fixes for hit target size, text clipping, Dynamic Type layout, and empty-state contrast.

## macOS

`StowMacUITests` queries the management Library, native Settings window, and bottom quick panel through the accessibility hierarchy. The Library exposes Inbox, Recently Used, Pinned, Archive, and Trash; one adaptive Filter menu and active summaries; single and multi-selection management; explicit editing actions; local failure feedback; Undo; and non-destructive Restore semantics. Stable identifiers and frame-containment assertions cover the filter bar, storage status, primary action, edit fields, feedback, and Settings recovery controls.

The Library is verified at 840×560, 1080×720, and 1440×900 with deliberately long app-owned status text and long user content. App-owned labels, statuses, recovery guidance, and actions must remain inside their window and wrap or disclose before clipping. Long user titles may use a bounded list preview only when their complete value remains available in detail, Help, and the accessibility value. Browsing detail does not change retrieval history. Dirty editing distinguishes Cancel from Save Changes, confirms discard, and retains the draft after failure.

Native Settings exposes Capture, Paste & Shortcuts, Sync & Storage, and Privacy. Long clipboard, shortcut-conflict, sync-pause, and search-rebuild failure text wraps in full-width rows with icon and text semantics. Permission requests remain explicit. Failed shortcut replacement restores the previous visible and registered pair; failed search rebuild keeps the previous usable index. The Settings visual matrix covers its minimum width, dark appearance, Reduce Motion, and Increase Contrast.

The unchanged Quick Panel still exposes its window, Clipboard/Inbox/Pinned modes, content-native cards, search field, removable filter tokens, no-results state, edit/preview popovers, Quick Add controls, and an always-visible `Close Quick Panel` control with stable labels and identifiers. Existing automated coverage retains the registered global shortcut from TextEdit, close routes, focus handoff, draft protection, stale search fallback, fullwidth input, handoffs, drag, keyboard actions, compact/narrow layouts, dark appearance, Reduce Motion, and Increase Contrast. Its approved visual baseline remains `docs/release/v0.1-quick-panel-visual-review.md`.

The owner-approved release scope does not use VoiceOver and is limited to the current single-display Mac. Named-control, status, focus, confirmation, keyboard-exit, and originating-app restoration assertions provide the macOS accessibility evidence; no multi-display check is required for v0.1.

## Privacy and sensitive previews

All root content is marked privacy-sensitive. When the iOS scene is inactive, Stow overlays saved content with an opaque material and a generic “Stow is private” message. Stow does not schedule notifications containing saved content.

## Localization readiness

All user-facing static SwiftUI literals use localized string-key initializers. `xcodebuild -exportLocalizations -exportLanguage en` successfully produced an English localization catalog. Dynamic item titles, content, filenames, dates, and source-app names intentionally remain user/system data rather than localization keys.
