# Stow Desktop Product Requirements

**Status:** Draft for review. This document describes the current macOS product scope. It does not approve a release or add a feature to the roadmap.

## Problem

Mac users copy links, text, code, images, and files as they work. Replacing the current clipboard contents can make earlier items hard to find. A clipboard history alone does not provide a place to pin, annotate, or archive items. Users need to save useful content, find it later, and reuse it in the app where they are working. They also need to stop capture when they handle private content.

## Goals and non-goals

- Save supported content automatically or deliberately. Keep it available after the current clipboard changes and when the Mac is offline.
- Make quick reuse a keyboard task. Use the Library for reviewing, editing, and organizing saved items.
- Let local coding agents use selected library content through an explicit command without opening the Library.
- Do not add team libraries, a developer-operated content service, remote automation, full webpage snapshots, OCR, or execution of saved code. iPhone and iPad features are outside this document except for shared-library sync.

## Requirements

| ID | Requirement | Acceptance check |
| --- | --- | --- |
| D-01 | **Automatic capture.** While Stow is running and monitoring is allowed, save supported new clipboard changes to Inbox. Let users stop monitoring in Capture settings or from the menu bar. Do not read protected or Stow-owned payloads. Do not capture content already on the clipboard when monitoring starts. | Start monitoring with a fixture already copied; it does not appear. Copy supported text, an HTTP/HTTPS link, an image, and a regular file; each appears in Inbox. Turn monitoring off and copy again; nothing is added. For every [excluded marker](../clipboard.md#excluded-clipboard-changes), verify zero payload reads. |
| D-02 | **Duplicates and formats.** Coalesce identical automatic captures without losing edits or lifecycle state. Never restore Trash by copying the same content. Preserve supported original formats within the [documented limits](../clipboard.md#preserved-original-formats), and offer a plain-text alternative. | Copy a fixture again after editing and pinning it. Confirm that it moves to the front of Clipboard with edits and pin intact. Repeat after moving it to Trash; confirm a new Inbox item and no change to the trashed item. Reuse rich text and an image with their original supported formats, then use Shift-Return on the text and verify that only plain text is written. |
| D-03 | **Deliberate capture.** Provide Quick Add from the menu bar and the default Option-Shift-S shortcut. Accept supported content from the macOS share extension after confirmation. Reject attachments over 100 MiB without creating a partial item. | Save a Quick Add draft and confirm it appears in Inbox. In a signed build, share a supported item from another app and confirm that Save adds one item and Cancel adds none. Test attachments at the limit and one byte above it. |
| D-04 | **Quick retrieval.** Open the quick panel from another app with the default Command-Shift-V shortcut. Let users navigate, search, preview, and reuse items without opening the Library. Combine query text with type, source-app, and date filters. | Open the panel from another app and begin typing. Confirm the first character is retained and the first matching item is selected. Use arrow keys, Space, and Return without a pointer. Apply a type filter and confirm that only items that match both the query and the filter remain. |
| D-05 | **Safe paste and exit.** Send a direct paste only to the originating app while it is frontmost and the build and system permit event posting. Otherwise copy the selection for manual paste. Show paste availability and monitoring state. Do not discard modified drafts without confirmation. | Test direct paste in a permitted build. Deny permission, use a sandboxed build, or close the originating app; Return must copy without sending Command-V to another app. Switch focus during the paste handoff and verify that no paste goes to the new app. Attempt to close a modified editor and keep the draft when the user declines to discard it. |
| D-06 | **Library and recovery.** Provide Inbox, Recently Used, Pinned, Archive, and Trash. Support search, editing, and single- and multi-item organization. Keep failed edits available for retry. Allow restoration before Trash is purged after 30 days during maintenance. | Search for a saved item, pin and archive a selection, restore archived items to Inbox, and move items to Trash. Verify Undo and restore. Test the retention boundary with a controlled clock. Force a save failure and confirm the saved item is unchanged and the draft remains editable. |
| D-07 | **Settings and layout.** Show capture, paste, shortcut, sync, and storage state. Keep a menu bar path to Settings when shortcut registration fails. Allow search index repair without changing saved items. Keep essential controls and status text readable and reachable at supported window sizes. | Try a conflicting shortcut pair and confirm the rejected pair is not saved. Rebuild the search index and confirm that saved items are unchanged. At the minimum supported sizes, verify that Close, search, status, and recovery controls remain usable without clipped or ambiguous text. |
| D-08 | **Local-first data.** Keep capture, search, and reuse available offline without an iCloud sign-in requirement. Sync through the user's private iCloud database when configured and available. Disclose that Mac link previews can make requests to page and image hosts. Do not send saved content to a developer-operated service. | Capture, find, and reuse fixtures offline. For sync, reconnect two signed devices on the same test iCloud account and verify that an offline change and its attachment arrive. Check the [privacy notice](../release/privacy.md) against preview requests and the configured data destinations. |
| D-09 | **Local CLI.** Let an explicitly invoked `stow` command search, retrieve, add, and export content under the same Mac user account. Support one JSON response per call, without prompts. Provide no remote access. | Follow the [CLI guide](../cli.md) with a test library. Add, search, get, and export a fixture. Retry a timed-out add with the same request ID and verify that it produces no duplicate. Confirm that JSON mode returns a local path for an export, not attachment bytes. |

## Success measures

- On the current Mac test host, complete the capture-to-reuse flow with the keyboard alone. Confirm that it still works offline and with Copy only, without requiring the Library.
- On the reference Apple-silicon Mac, use the [accepted performance targets](../decisions/0001-v0.1-foundation.md): warm launch under 1 second, capture commit under 1 second after provider loading, and quick panel presentation under 250 ms. For 10,000 mixed items, measure local search under 50 ms median and 150 ms at the 95th percentile, and index rebuild under 5 seconds.
- Record results against the [release test matrix](../release/v0.1-test-matrix.md). Product usage targets are not defined. Do not treat this draft or existing test scenarios as new evidence of a pass.

## Dependencies and open questions

- **Platform:** macOS 14.0 or later. The routine [automated UI scope](../decisions/0004-v0.1-test-scope.md) is the current macOS host. Desktop verification defaults to one display without VoiceOver; this is a test scope, not a compatibility claim.
- **Permissions:** macOS controls background clipboard access separately from direct paste. The app's sandbox configuration blocks direct paste in the current sandboxed build. Verify Copy only and its status in the signed candidate; do not advertise direct paste for a build that cannot post paste events.
- **Distribution:** The [remaining release checklist](../release/v0.1-external-unblock.md) calls for macOS share-extension provisioning, signed archive validation, production CloudKit deployment, and signed two-device verification. The repository does not document a public Mac download or release date.
